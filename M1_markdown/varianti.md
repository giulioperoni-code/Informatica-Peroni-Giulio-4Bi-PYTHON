# Le varianti di Markdown a confronto

| Costrutto | Markdown originale | CommonMark | GitHub Flavored Markdown |
| :--- | :---: | :---: | :---: |
| Blocchi di codice recintati | Supportato con sintassi base | Supportato in modo uniforme | Supportato con evidenziazione avanzata |
| Tabelle | Non standard | Supportato | Supportato con estensioni aggiuntive |
| Caselle di spunta | Non standard | Non standard | Supportato in modo nativo |
| Testo barrato | Non standard | Non standard | Supportato |
| Collegamenti automatici | Non standard | Non standard | Supportato |
| Note a piè di pagina | Non standard | Non standard | Supportato |

## Esempi con GitHub Flavored Markdown

- [x] Controllo i link esterni
- [ ] Verifico le tabelle nel file
- [x] Controllo la sintassi del documento
- [ ] Aggiorno il contenuto dopo la revisione
- [ ] Confronto il risultato con l'anteprima
- [ ] Rivedo la struttura delle sezioni

~~Questa versione del documento è obsoleta e va sostituita con la revisione corrente.~~

Il collegamento automatico `https://www.markdownguide.org/` diventa cliccabile quando viene scritto come URL completo.

Per le consegne del corso conviene usare GitHub Flavored Markdown, perché rende più stabile la resa del documento e supporta funzionalità pratiche come le caselle di spunta, il testo barrato e i link automatici. In uno strumento che implementa solo CommonMark, alcune di queste funzioni non compaiono oppure vengono visualizzate in modo più semplice, senza la stessa esperienza di GitHub. Questo file, aperto con un parser minimale, potrebbe mostrare meno estensioni e quindi non riflettere correttamente l'aspetto finale previsto nelle consegne.
